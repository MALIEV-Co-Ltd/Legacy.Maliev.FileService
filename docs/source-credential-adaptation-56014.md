This finite mapping covers source commit `56014f2efc7c7f24b777c51d17a454e023d12bdd`, parent `b6c8c6a18f2a782b59f988c24f5e48a30c51cfe0`, against retained checkpoint `135e526d0dab85c415b3afdcefd7b70fe2c82e2f`. Original source history and credential resource values are not copied.

The retained source supports an optional externally mounted `GoogleCloudStorage:CredentialsPath`, otherwise ADC, and shares a cached credential between its storage client and signer. This service follows its existing [repository policy](../AGENTS.md), [source identity adaptation](source-identity-obligations.md), and [recovery design](file-storage-recovery-design-20261001.md): ADC/GKE Workload Identity acquisition, no legacy credential-file loader or embedded credential resource. The optional source configuration key is deliberately unsupported. This is an approved architecture adaptation, not preservation of the old file-loading behavior or proof of configured runtime identity.

Current registration creates one singleton `StorageClient`, then obtains its singleton signer through `CreateUrlSigner`. That SDK method uses the client's credential, as documented in the [Google StorageClient reference](https://docs.cloud.google.com/dotnet/docs/reference/Google.Cloud.Storage.V1/latest/Google.Cloud.Storage.V1.StorageClient#Google_Cloud_Storage_V1_StorageClient_CreateUrlSigner). Both the source changing commit and final source already clamp signed URLs to seven days. Current signing keeps that bound and explicitly uses V4; source XML remarks describing longer validity do not override the executed clamp. The removed `IServiceAccount`/`ServiceAccount` wrappers and credential resource accessor/data remain superseded. Generated XML file removal does not retire public API or adapter documentation; modern project documentation and actual tests carry those requirements.

The new [registration regressions](../Legacy.Maliev.FileService.Tests/Api/CredentialRegistrationCompatibilityTests.cs) exercise the real `AddFileServiceRuntime` registration and storage adapter. They inject one actual SDK client with an ephemeral RSA credential, resolve its real shared signer, and sign one-hour/seven-day/oversized-duration URLs. Rejecting HTTP factories guard both credential and storage transports. The tests verify credential identity, singleton reuse, V4 expiry and no transport requests. Separate cases resolve disabled storage without registering a client/signer and reject a nonsigning credential. The old optional file-loader test is intentionally replaced by ADC-only compatibility checks rather than a new loader.

These are synthetic, offline code-boundary fixtures. They do not load ambient ADC, use credential files, contact Google, access real objects, establish deployment identity, or establish IAM grants. Existing clean-metadata, authorization, generation and HTTP signing checks remain applicable; direct adapter signing fixtures do not replace them. No production registration, storage workflow, runtime flags, package pins, deployment or resources change in this slice.
